## 三、逐版改造明细

### v1.0.6（2026-10-24）

| # | 改造 | 文件 | 为什么必须改 |
|---|---|---|---|
| 1 | `__warmRealFp()` 预热轮询 + `HKCU\Software\Typora\MFp` 缓存 | `typora_crack.js` | Typora 取机器码是**异步**的（handler 返回 Promise，实测 2ms 后才 resolve），而首次许可校验是**同步**取 fingerprint。只在 Hook 里临时取一次必然慢半拍，实体只能用打包机指纹 → 换任何机器都 `no info` → 回 15 天试用。改为在 jsc 加载前就轮询（实测 70–80ms 就位 vs 校验 250–310ms），并把结果落注册表供后续启动同步命中 |
| 2 | 启动器 `START-Typora.exe`（C#，6.5–7KB） | `scripts/launcher/Program.cs`、`scripts/build-launcher.sh` | 原 `.bat` 里塞内联 PowerShell：引号、`%` 展开、`&|()` 转义、编码四件事一起踩，且失败静默（「桌面没图标」就是这么来的）。改用 `WScript.Shell` COM 建 `.lnk`，不受执行策略/MOTW 影响，出错弹 MessageBox |
| 3 | 首次运行标记三态（无 / `done` / `removed`）+ 每次启动自检 | 同上 + `SETUP.bat` | 原来用「包内 `.lnk` 是否存在」判断首次运行，而那个文件会随包发行 → 用户机永不建快捷方式。改包外标记 `%LOCALAPPDATA%\TyporaGreen.setup-done`；`done` 状态下快捷方式被删或 target 不是当前包就重建；`SETUP.bat` 选 3 写 `removed`，之后不再自动建回 |
| 4 | 脚本版发行包去掉 `typora-his\` | 打包规范（`DOC/BUILD-SCRIPT.md`、SOP） | 包根固定 5 项、约 70MB。带 Typora 安装包会到 260MB+，且是官方版权物的重复分发 |
| 5 | 开发者文档 `DOC/`（6 篇） | `DOC/` | 让别人能自己构建绿色版/脚本版包、改启动器、发版、排错 |

**验证方式**（详见 CHANGELOG 1.0.6 的逐项记录）：烘焙指纹与 deviceId 全改成假值 + 全新 profile + 无缓存 → 仍 `[L] pass`；启动器 8 项矩阵（首次/自愈/改名/removed/中文路径/缺 exe/点图标启动）全过；真实包跑一遍 `[L] pass`。

## 四、怎么用这张表

- **想知道某功能哪版加的** → 查第二节「首次生效版本」
- **想改某块逻辑** → 查「落在哪」，再去对应文件；改注入模板务必读 [TROUBLESHOOTING.md](TROUBLESHOOTING.md) 的判据表
- **发新版** → 按 [RELEASE.md](RELEASE.md) 走，并在本表第二节、第三节各加一行
- **回退到某版行为** → 以第一节的标签为基线（`git checkout v1.0.x`），注意 v1.0.5 的已知缺陷
